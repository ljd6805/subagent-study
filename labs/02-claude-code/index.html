/permissions

/permissions: 지금 적용되는 allow·ask·deny 규칙과, 각 규칙이 어느 설정 파일에서 왔는지 보여 준다.

왜 Manual로 고정하나

2.1.283부터 대화형 세션은 auto 모드로 시작한다. auto에서는 분류기가 대신 판단해서 권한 요청이 거의 뜨지 않고, subagent에 정한 permissionMode도 무시된다. 이 덱은 Manual(설정값 "default")에서 확인한다.

위임을 막는 설정이 있는지

회사나 개인 설정의 deny에 Agent가 있으면 위임 자체가 안 된다. 환경 변수 CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1이면 Explore와 Plan이 빠진다(0-3 목록으로 확인).

  • 입력창 아래에 auto mode on 같은 모드 표시가 없다
  • /permissions의 Deny 쪽에 Agent로 시작하는 규칙이 없다
권한 요청에서 "Yes, and don't ask again"은 고르지 않는다. 규칙이 저장소 맨 위 .claude/settings.local.json에 저장되어 뒤 실습 결과가 달라진다.

stream-json으로 받으면 어떤 자식이 불렸는지 스크립트로 셀 수 있다

$ jq -c 'select(.type=="assistant" and .parent_tool_use_id==null)
    | .message.content[] | select(.type=="tool_use" and .name=="Agent")
    | .input | {subagent_type, description}' run.jsonl

$ jq -r 'select(.parent_tool_use_id != null) | .parent_tool_use_id' \
    run.jsonl | sort | uniq -c

# 마지막 result 줄: 턴 수, 비용, 쓴 모델
$ jq -c 'select(.type=="result")
    | {num_turns, total_cost_usd, models: (.modelUsage | keys)}' run.jsonl

PS> claude -p --output-format stream-json --verbose `
    "tests 와 minishop 폴더를 Explore subagent 두 개에게 동시에 조사시켜 줘" `
    > run.jsonl
PS> $ev = Get-Content run.jsonl | ConvertFrom-Json

# 부모(parent_tool_use_id가 비어 있음)가 부른 Agent만
PS> $ev | Where-Object { $_.type -eq 'assistant' -and -not $_.parent_tool_use_id } |
    ForEach-Object { $_.message.content } |
    Where-Object { $_.type -eq 'tool_use' -and $_.name -eq 'Agent' } |
    ForEach-Object { $_.input } | Select-Object subagent_type, description

# 자식 사건 수: 어느 Agent 호출 아래에서 나왔는지로 묶기
PS> $ev | Where-Object parent_tool_use_id | Group-Object parent_tool_use_id -NoElement

# 마지막 result 줄: 턴 수, 비용, 쓴 모델
PS> $ev | Where-Object type -eq 'result' | Select-Object num_turns, total_cost_usd,

return subtotal - discount_percent

if self.available(name) > qty:

def top_products(orders, n=3):
