  • 목록에 explore, general이 (subagent)로 보인다
0-4 · 시작 전 점검

build agent에 task 도구가 켜져 있어야 위임이 된다

할 일1왼쪽 첫 명령을 실행해 true인지 본다2false면 둘째 명령으로 task 규칙을 보고 오른쪽 설명을 따른다3opencode.json은 이미 들어 있으니 만들지 않는다
terminal · minishop 폴더
opencode --pure debug agent build | jq .tools.task
true   ← 이래야 정상

# false라면 task 규칙을 본다 (마지막 줄이 적용됨)
opencode --pure debug agent build \
  | jq -c '.permission[] | select(.permission=="task")'
{"permission":"task","pattern":"*","action":"deny"}
$a = opencode --pure debug agent build | Out-String | ConvertFrom-Json
$a.tools.task
True   ← 이래야 정상

# False라면 task 규칙을 본다 (마지막 줄이 적용됨)
$a.permission | Where-Object permission -eq 'task'
permission action pattern
task       deny   *
opencode.json · minishop 폴더에 이미 들어 있음{
  "$schema": "https://opencode.ai/config.json",
  "permission": { "task": "allow" },
  "agent": {
    "build": { "permission": { "task": "allow" } }
  }
}
task가 꺼져 있으면

task 규칙의 마지막이 * deny이면 OpenCode가 task 도구를 목록에서 빼 버린다. 모델은 "task 도구가 없다"고 말하며 subagent를 부르지 못한다.

어디서 들어오나

기본값에는 없다. 흔한 원인은 플러그인이다. 예를 들어 oh-my-openagent(옛 이름 oh-my-opencode)는 build를 subagent로 바꾸고 task를 막으며, explore도 자기 것으로 바꾼다. 그래서 이 덱의 모든 명령에는 --pure가 붙어 있다. 플러그인 없이 OpenCode 기본 상태로 실행한다는 뜻이다. 전역 설정의 permission이 원인이면 왼쪽 파일이 이 폴더에서만 다시 연다.

  • tools.task가 true다
  • opencode --pure agent list가 0-3과 같은 일곱 개다

1-2 · 자식 세션 들어가기

자식 세션은 따로 저장되고, 들어가서 볼 수는 있지만 말을 걸 수는 없다

할 일11-1 대화 화면에서 ctrl+x를 눌렀다 떼고 ↓를 눌러 자식 세션에 들어간다2자식 입력창에 글을 써 보고 막히는지 본다3ctrl+x ↑로 부모에 돌아온다
ctrl+x ↓첫 번째 자식 세션으로 들어가기 (ctrl+x가 기본 leader 키) →다음 자식 세션 ←이전 자식 세션 ↑부모 세션으로 돌아가기 ctrl+p명령 목록. 도구 호출이 안 보이면 Show tool details를 고른다 (도구 결과 내용까지 보려면 Show generic tool output)
자식 세션 입력창에 글을 쓰려고 하면 막힌다. 자식에게 더 시키려면 부모에게 부탁해야 한다 (LAB 5의 이어서 시키기).
1-3 · 부모와 자식 비교

파일을 읽은 흔적은 자식에만 남고, 부모는 결과 한 덩어리만 받는다

할 일11-1 대화에서 부모와 자식 세션을 오가며(1-2 키) 왼쪽·오른쪽 항목을 하나씩 세어 본다2아래 체크 두 가지를 적어 본다
부모 세션에서 세어 보기
  • 도구 호출: task 1개 (부모가 직접 read를 했다면 그것도 센다)
  • task 블록 안의 결과: 자식의 마지막 답 텍스트
  • 자식이 읽은 파일 내용은 부모 대화에 없다
자식 세션에서 세어 보기
  • 도구 호출: glob, read, grep 등 여러 개
  • 첫 메시지: 사용자가 쓴 문장이 아니라 부모가 새로 쓴 지시문
  • 부모와 나눈 앞선 대화는 자식에게 없다
  • 자식 세션의 첫 메시지를 읽고, 내가 입력한 문장과 어떻게 다른지 적어 본다
  • 자식 세션의 도구 호출 수와 부모 세션의 도구 호출 수를 비교한다
이론 덱의 "들어가는 것은 브리프, 나오는 것은 결과, 넘어가지 않는 것은 중간 과정"을 화면으로 확인하는 단계다.

5-1 · 브리프 쓰기

자식은 앞선 대화를 모르므로, 브리프 하나로 일이 끝나야 한다

brief.md · minishop 폴더에 저장, <대상>만 바꿔 쓴다## 목표
minishop/<대상>.py 의 버그나 미완성 부분을 찾아 고친다.

## 범위
- 고쳐도 되는 파일: minishop/<대상>.py 하나
- tests/ 와 다른 모듈은 읽기만 한다

## 완료 조건
- python -m unittest tests.test_<대상> 이 통과한다
  (Linux·macOS에서는 python3)
- 고칠 것이 없으면 고치지 않고 그렇게 보고한다

## 결과 형식
reports/<대상>.md 파일에 아래 네 줄을 쓴다.
상태: 고침 | 문제 없음 | 막힘
원인: (한 줄)
바꾼 곳: 파일:줄
테스트: 통과 N / 실패 N
브리프의 네 칸
  • 목표: 무엇을 끝내야 하나
  • 범위: 어디까지 손대도 되나 (동시 작업 충돌 방지)
  • 완료 조건: 끝났는지 무엇으로 판단하나
  • 결과 형식: 무엇을 어디에 남기나

범위를 파일 하나로 나누어 두는 것이 중요하다. 세 자식이 같은 파일을 동시에 고치면 서로의 수정을 덮어쓴다.

report.py 를 맡았던 subagent에게, 같은 task_id로 이어서 top_products 테스트를 tests/test_report.py 에 추가하라고 해 줘.
task_id가 하는 일

id는 자식 세션의 id다. 부모가 task를 부를 때 이 값을 task_id로 넘기면 새 세션이 아니라 그 세션에서 이어진다. 자식은 앞에서 읽은 파일과 대화를 기억한다.

  • 새 자식 세션이 생기지 않고, 기존 report 담당 세션에 메시지가 이어 붙었다
  • 자식이 report.py를 다시 읽지 않고 바로 테스트를 썼는지 확인했다

새로 맡기기와 이어서 시키기 중 무엇이 나은지는 앞의 맥락이 도움이 되는지로 정한다.

6-2 · JSON으로 task 보기

--format json으로 받으면 어떤 자식이 불렸는지 스크립트로 셀 수 있다

할 일1왼쪽 첫 명령을 실행해 run.jsonl이 생기는지 본다2둘째 명령으로 task만 골라 본다
terminal
opencode --pure run --format json \
  "tests 와 minishop 폴더를 explore subagent 두 개에게 동시에 조사시켜 줘" \
  > run.jsonl

# 부모가 부른 task만 골라 보기
jq -c 'select(.type=="tool_use" and .part.tool=="task")
       | .part.state.input
       | {subagent_type, description}' run.jsonl

# 출력 예
{"subagent_type":"explore","description":"tests 폴더 조사"}
{"subagent_type":"explore","description":"minishop 폴더 조사"}
opencode --pure run --format json `
  "tests 와 minishop 폴더를 explore subagent 두 개에게 동시에 조사시켜 줘" `
  > run.jsonl

# 부모가 부른 task만 골라 보기
$ev = Get-Content run.jsonl | ConvertFrom-Json
$ev | Where-Object { $_.type -eq 'tool_use' -and
                     $_.part.tool -eq 'task' } |
  ForEach-Object { $_.part.state.input } |
  Select-Object subagent_type, description

# 출력 예
subagent_type description
explore       tests 폴더 조사
explore       minishop 폴더 조사
JSON 출력에 담기는 것
  • 한 줄에 사건 하나. 끝난 도구 호출은 type: "tool_use"
  • 부모 세션의 사건만 나온다. 자식 안의 read, grep은 안 나온다
  • task의 state.output에 <task_result>가 들어 있다
  • task 두 개가 잡혔다
  • state.output에서 자식 세션 id(ses_...)를 찾았다

이 방법으로 LAB 2-5의 description 실험을 여러 번 자동으로 돌려 셀 수 있다.

Summary

OpenCode 실습에서 직접 확인한 것

선언
  • .opencode/agents/이름.md 또는 opencode.json의 agent
  • 필수는 description, 나머지는 선택
  • debug agent로 모델 없이 검사
제한
  • permission: 도구별 allow / ask / deny, 마지막 일치 규칙
  • permission.task: 맡길 대상
  • mode, subagent_depth: 누가, 몇 단계까지
운용
  • 브리프 네 칸: 목표, 범위, 완료 조건, 결과 형식
  • 여러 task를 한 번에 → 동시 실행
  • 판정은 테스트로, 이어서 시킬 땐 task_id
다음 실습은 같은 순서를 Claude Code로 옮긴다. 샘플 프로젝트 minishop을 그대로 쓰므로, 두 도구에서 같은 요청이 어떻게 다르게 처리되는지 비교할 수 있다.
Appendix · 정답

minishop에 숨겨 둔 문제 세 가지

버그 1 · cart.py
return subtotal - discount_percent

할인율(%)을 금액처럼 뺐다. subtotal * (100 - discount_percent) / 100이 맞다. test_total_with_discount가 실패한다.

버그 2 · inventory.py
if self.available(name) > qty:

남은 수량을 전부 예약하는 경우를 막는다. >=가 맞다. test_reserve_all_remaining이 실패한다.

미완성 · report.py
def top_products(orders, n=3):
    raise NotImplementedError

판매 수량 순 상위 n개. 테스트가 없어서 테스트 실행만으로는 드러나지 않는다. 기대값: mouse 10, cable 10, keyboard 3.

mouse와 cable이 10개로 같다. 같은 수량일 때 순서를 어떻게 정할지는 정해져 있지 않으므로, 자식이 이 점을 보고했는지도 확인해 볼 만하다.
